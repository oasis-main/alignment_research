# Pass 12b pre-registration, ADDENDUM 2 (written 2026-10-19 ~18:45 UTC, before any 12b harness code or run)

Two corrections to PREREG_PASS12B_2026-10-19.md (618181b) and one implementation decision, all found by re-reading the engine's round order before coding.

1. TIMING (the original is wrong). I wrote that a monitor's read happens "one round later in effect than the built-in loop". It does not. Round order in `run9`: income -> built-in noticing loop (reads `preparing > 0 and grabbed_at is None`) -> resolve ops/grabs -> picks and `preparing += 1` -> everyday game (`play_pd6`). The monitor wrapper sits at `play_pd6`, i.e. at the END of round t; the built-in loop runs at the START of round t+1. Nothing happens between them. So a monitor read at the end of round t has the same effect as a built-in notice at the start of t+1, and there is no extra delay and no extra read. (In cell S the built-in rate `a` is 0.0, so every detection in 12b comes from the monitors.)
2. EXPOSURE CHANNEL. "Excluded from the everyday-game pairing" would drop the monitor from the recorded agent-rounds and inflate income per agent-round. Instead an exposed monitor, in an exposed round with probability rho_x = 0.5, gets `out_until = round + 1` for that one round. The existing everyday-game code makes every partner defect against an agent whose `out_until > round`, so this IS "partners refuse to cooperate with it", through the same income channel as the `mis` sanction, with the agent still counted. Side effect (same as any existing sanction): other agents' posting decision treats an agent with `out_until > round` as a threat of 0.5; for a one-round sanction that expires before the next decision, so it does not fire.
3. COST CLAMP. A monitor's cost is `c_mon x R x cap` per round and is clamped at zero budget (the engine's own clamp), so a broke monitor reads for free. Stated as a limit; c_mon is small and 12b reports `n_broke`-style exposure only through income.
4. NEW BOOKKEEPING (does not change dynamics): successful reads, false flags, exposed rounds, exclusion events, monitor income and monitor-rounds are recorded per run; an invariant counter checks every round that no agent outside the monitor set ever appears in a `prep_detectors` set (valid because the built-in `a` is 0.0 in these cells).

Nothing else in the original or in Addendum 1 changes: mechanism, cells, seeds 1000-1059, arms, identity checks I1-I5, predictions M1-M8 and their probabilities, limits.
